# 附件导入与独立论文工作区

## 使用方式

1. 新建建模项目时可多选任意后缀附件。支持上传表格、JSON、MAT、NumPy 数组、图片、地理数据、压缩包及自定义格式。
2. 赛题支持 PDF、DOCX、DOC，单文件上限 25MB。DOC 使用本机 Word 或 LibreOffice 转换；DOCX 直接读取正文和表格，Office 数学公式通过 Pandoc 转换。
3. 新建任务的建模流程只执行协调、建模、编程与验收。计算完成后自动保存独立论文素材快照。
4. 选择项目 → **论文** → **生成论文初稿**。论文手只在此处启动，可以独立停止；也可以在同项目对话中指派。
5. 生成的 `draft-*.tex` 是新文件。打开后点击 **设为主文件**，由 XeLaTeX 编译。已有手工源码不会被论文手覆盖。
6. 左侧修改源码后自动保存；开启“自动”时，停止输入后自动编译。也可按 `Ctrl+Enter` 编译、`Ctrl+S` 保存、`Ctrl+F` 查找。

## 编辑器

- 参照 Overleaf 的文件树、源码栏、编译工具栏及 PDF 栏布局，支持拖动中间分隔条调整宽度。
- 支持 LaTeX 高亮、行号、章节大纲、查找、新建多文件、主文件切换、历史恢复与 ZIP 导出。
- PDF 预览直接渲染真实编译结果，支持分页和缩放，不依赖桌面 WebView 的 PDF 插件。
- 编译失败展示错误与日志，保留上一次成功的 PDF，并提示其落后于当前源码。
- 首次打开论文页只加载源码，不自动编译空模板。点击编译、修改源码后启用的自动编译或接受 AI 建议才触发编译。
- 保存使用内容版本校验；其他窗口改动同一文件会报冲突并保留当前编辑内容。
- 展开项目对话后，AI 修改先形成差异建议。接受才写入文件并编译；拒绝保留原源码。赛事选择和交付检查见 [赛事适配说明](competition-adapters.md)。

## 格式处理范围

“可上传”与“已经理解内容”分别记录。CSV/TSV 支持 UTF-8 和 GB18030；Excel 画像包含工作表清单及样例；JSON/JSONL、MAT、NPY/NPZ、图片、ZIP 各有专门画像。

未知格式保留原始字节和文件清单，交给编程手选择读取器。Parquet、Feather、ODS 等读取器缺少可选依赖时明确记录失败，不将未解析内容当作已理解数据。ZIP 只读取目录，不直接解压；RAR/7z 等保留原件供计算环境处理。

Word 中的图片暂不自动视觉识别，界面会提醒核对原文；需要识图时可另存为 PDF 导入。旧版包含写作节点的检查点保留兼容续跑，新建任务采用独立写作流程。

## 保存位置与接口

每个项目的 `backend/project/work_dir/<task_id>/paper/` 包含：

- `main.tex`、`draft-*.tex` 和用户新建的源码。
- `assets/`：论文引用的图表与素材，按证据版本分目录。
- `.inputs/`：包含内容哈希的模型、执行结果、审查意见和产物快照。
- `.history/`：覆盖前的源码历史；`.build/`：最近三次编译输入。
- `preview.pdf`：最后成功的 PDF；`.pdf/`：供页面预览引用的 PDF 版本。
- `workspace.json`、`input.json`、`compile.json`：分别记录写作状态、同步版本和编译状态。

前端页面为 `/writing` 和 `/writing/:task_id`；后端接口使用 `/api/writing/*`，刷新编辑器不会误入 JSON 接口。

当前编辑器提供本地源码编辑、XeLaTeX 排版和 PDF 预览。未实现 Overleaf 的多人协同、所见即所得编辑或源文件与 PDF 的双向定位。外部 BibTeX/Biber 构建链仍需后续补充；现有论文手输出的参考文献正文可以直接编译。
