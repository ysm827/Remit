# 对话驱动的团队工作区

## 使用方式

- `/home` 是对话首页。可直接描述赛题，也可导入 PDF / Word 和任意后缀数据附件。提交时保留计算环境和竞赛模板选项。
- `/project/<id>` 与 `/task/<id>` 打开统一项目；右上角可展开共享状态表。
- 「文件与结果」集中显示题意、模型、计算结果和文件，旧阶段地址重定向到此视图。
- 「论文」提供源码 / PDF 编辑器与可展开的同项目对话；`/writing/<id>` 兼容重定向。
- 左侧完成项目搜索、重命名、归档与恢复；归档项目菜单可永久删除，确认框列明对话、附件、代码、结果与论文均会删除。执行中的项目禁止删除；纯聊天项目无需旧版历史记录即可删除。`/projects` 重定向到统一首页。
- 问候语也调用已配置的协调模型并携带对话上下文，没有固定回复或人为延迟。历史同步标记保留在内部日志，不显示为用户可见的执行记录。
- 首页及后续对话的输入框 `+` 均可添加 PDF / Word、多个数据附件或整个数据文件夹。文件夹按原有相对路径导入，包含子目录，不同目录的同名文件各自保留；首页以文件夹名称和数量显示。隐藏和系统文件跳过并提示数量。默认每批最多 1000 个文件，单文件 128MB、合计 512MB；保留服务端配置覆盖值。
- 建模前补充附件会更新准备计划，仍需确认才能开始。建模开始后也可导入附件，保留当前检查点与成果，不自动重算；后续模型调用可见文件清单，远程计算执行前增量同步新附件。新数据同样受返修清理保护。
- “文件与结果”显示完整相对路径并支持搜索，内部隐藏文件不展示，下载地址随清单一次返回。
- 普通聊天与概念问题只回复；提供具体建模任务时才预读并确认计划，再开始建模。对话保留用户原文，不替换成内部指令。总体模型方案和最终结果需要验收。赛事配置见 [赛事适配说明](competition-adapters.md)。
- 左上角按钮可折叠或展开项目侧栏，桌面折叠状态跨刷新保存。
- 侧栏以 220 ms 滑动收合，正文宽度同步变化；收起后导航退出键盘焦点顺序，遵循系统减少动态效果设置。
- 项目页使用单行顶栏。助手正文无框并支持 Markdown/公式排版，用户消息为淡灰气泡；连续执行记录合为可展开的一行，筛选与展开全部记录位于右上角显示选项。
- 建模运行中发送新消息时，选择「立即调整」或「当前步骤完成后调整」。前者先取消旧步骤并等待退出，再携带新要求恢复，不能绕过验收；后者在当前步骤成功完成后发布要求，不影响本步骤内的重试。若停止超时或状态变化，会明确提示查看进度再继续。

可发送的指令示例：

1. `请代码手在下一轮保存逐样本预测值和误差图。`
2. `解释目前的模型和验证结果。`
3. `请建模手重做总体方案，验证改为按时间切分。`
4. `批准当前步骤`，或在成果验收卡中批准。
5. `停止建模`、`继续执行`、`停止论文手`。
6. `请论文手根据已验收结果撰写论文，重点解释局限。`
7. `编译当前论文`。

对话由已配置的协调模型解释成受约束动作。执行器重新检查任务状态、可恢复节点与验收版本，然后调用实际工作流、论文生成或编译入口。模型的文字回复不能把任务标成完成。

运行中补充的角色要求在下一次模型调用时生效；已发出的模型请求不会被追溯改写。需要立即终止时使用停止动作。建模成果未完成验收前，论文手不会使用未通过的结果生成正文。

## 共享状态与事件

- `workflow_state.json` 是建模阶段的执行事实；`paper/workspace.json`、`paper/compile.json` 是写作和编译的执行事实。
- 每个项目的 `.team.sqlite3` 保存不可变事件、幂等命令、角色要求及读取回执。
- 前端与每次角色调用均读取 `team_state.snapshot` 的投影，不各自维护一套推测进度。新要求不会被第一个读取的 Agent 消耗掉。
- 检查点保存记录步骤开始、完成、验收、停止与返修；已有 Agent / 工具消息及活动进入同一日志。论文事件仍与建模生命周期隔离。
- `/api/team/<id>/stream` 使用 SSE，每 750 ms 检查新事件。事件有单调序号，断线通过 `Last-Event-ID` 补齐；刷新从持久化日志恢复。长记录分批传输，前端保留完整记录并允许展开历史。
- 状态表显示当前已知步骤。协调者拆分出新问题后会增加步骤，分母随之变化。
- 重发同一请求编号只执行一次。服务重启会标记未结束的调度为中断，不自动重放有副作用的命令。
- 停止动作可绕过正在等待协调模型返回的普通命令；在停止之前尚未派发的动作会被撤回。

## 目标核对

| 要求 | 实现与证据 |
| --- | --- |
| 所有 Agent 共同维护进度 / 全局状态 | 检查点、角色消息、写作和编译更新共享事件；每次 LLM 调用刷新同一状态，按角色登记读取回执。并发回归通过。 |
| 首页以对话交互为主 | 新首页和默认项目入口均为 TeamChat；桌面三栏和手机折叠状态表已实测。 |
| 对话控制建模、编程、论文角色 | 受约束协调动作调用真实工作流 / 论文入口；真实协调模型派发要求和真实编译已验证，其他副作用边界有回归覆盖。 |
| 每一步在前端显示 | 持久化事件序号、SSE 实时传输、工具详情、人工验收卡、共享步骤表；刷新和重连测试通过。 |
